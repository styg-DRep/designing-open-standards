## Intent

Organize documentation into four modes — tutorials, how-to guides, reference and explanation — each answering a different reader's question.

## Tutorials — Learning

Question:

> **How can I learn this by doing?**

Characteristics:

- guided;
    
- sequential;
    
- safe;
    
- concrete;
    
- beginner-oriented.
    

Examples:

- create your first valid governance record;
    
- publish a sample proposal using the standard;
    
- validate a simple implementation.
    

Tutorials optimize for successful learning, not exhaustive coverage.

---

## How-To Guides — Tasks

Question:

> **How do I accomplish this particular thing?**

Characteristics:

- problem-oriented;
    
- concise;
    
- assumes some knowledge;
    
- task specific.
    

Examples:

- extend the vocabulary;
    
- migrate from version 0.4 to 0.5;
    
- map an existing governance dataset;
    
- submit a change request.
    

---

## Reference — Lookup

Question:

> **What exactly does the standard say?**

Contains:

- normative specification;
    
- schemas;
    
- vocabulary definitions;
    
- identifiers;
    
- constraints;
    
- API descriptions;
    
- conformance rules;
    
- version information.
    

Reference should prioritize precision and completeness.

---

## Explanation — Understanding

Question:

> **Why is the standard designed this way?**

Contains:

- conceptual model;
    
- design rationale;
    
- tradeoffs;
    
- architecture;
    
- relationship to adjacent standards;
    
- history;
    
- limitations.
    

This is where someone learns **why**, not merely **what**.
