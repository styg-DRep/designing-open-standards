## Intent

Identify the people, groups and institutions participating in the governance activity relevant to the proposed standard.

Avoid beginning with formal governance categories alone.

Map actors by what they actually do.

Three initial lenses are especially useful:

### Producing governance activity

Who creates things that governance depends upon?

Examples might include people who:

- author proposals;
    
- draft standards;
    
- develop governance tools;
    
- create analyses;
    
- create metadata or records;
    
- operate infrastructure;
    
- moderate deliberation;
    
- maintain repositories;
    
- publish decisions;
    
- implement approved changes.
    

### Using governance infrastructure

Who depends upon existing governance systems to act?

This may include:

- voters;
    
- DReps;
    
- SPOs;
    
- Constitutional Committee members;
    
- proposers;
    
- delegates;
    
- reviewers;
    
- developers;
    
- researchers;
    
- communities;
    
- treasury participants;
    
- tool builders;
    
- observers.
    

The categories should emerge from the domain rather than being treated as fixed Cardano constitutional roles.

### Exchanging governance information

Who produces, transforms, relays, interprets or consumes governance information?

Look for:

- proposal metadata;
    
- rationales;
    
- voting records;
    
- deliberative records;
    
- analyses;
    
- standards;
    
- recommendations;
    
- status information;
    
- implementation information.
    

An actor may occupy several categories simultaneously.

## Working pattern: Actor–Activity–Object

For each actor, record:

**Actor → activity → governance object**

For example:

> DRep → evaluates → governance action

> Tool developer → transforms → proposal metadata

> Community group → interprets → governance impact

This is usually more informative than assigning actors a static label.
