An Ecosystem Map should be capable of showing:

- actors;
    
- activities;
    
- governance objects;
    
- infrastructure;
    
- information flows;
    
- relationships;
    
- dependencies;
    
- existing standards;
    
- areas of control;
    
- institutional and syndication effects;
    
- important tensions;
    
- prospective collaborators;
    
- uncertainties.
    

The map need not contain all of this visually at once.

The important thing is that the underlying inquiry has considered these dimensions.

---

# Pattern: Map Claims With Confidence

Not everything on an ecosystem map should appear equally certain.

Tag important claims where useful:

- `observed`
    
- `reported`
    
- `inferred`
    
- `assumed`
    
- `contested`
    
- `unknown`
    

For example:

> Tool X is the dominant governance interface — `inferred`

is very different from presenting dominance as an established fact.

This becomes particularly important when mapping influence and control.

---

# Pattern: Preserve the Unmapped

An ecosystem map should include known unknowns.

Create explicit placeholders for:

- missing communities;
    
- unclear infrastructure;
    
- unexplained relationships;
    
- conflicting accounts;
    
- inaccessible information;
    
- suspected dependencies.
    

A blank area that has been noticed is more valuable than false completeness.
